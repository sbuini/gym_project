# 智慧体育馆管理系统论文内容整理（Markdown版）

## 题目

基于 Spring Boot 与 Vue 3 的智慧体育馆管理系统设计与实现

## 摘要

随着全民健身需求增长，传统体育场馆在预约管理、用户运营与资源调度方面暴露出效率低、体验差的问题。本文围绕“智慧体育馆管理系统”展开设计与实现，构建了一个前后端分离的 Web 系统：后端采用 Spring Boot + Spring Data JPA，前端采用 Vue 3 + Vite，并结合 MySQL/H2 完成数据存储。系统面向普通用户与管理员两类角色，提供场馆浏览、预约下单、签到入场、收藏、评分、余额充值与后台管理等能力；同时引入协同过滤思路实现个性化推荐，提升用户发现效率。实践结果表明，该系统能够在中小规模场馆业务中稳定支持核心流程，具备较好的可维护性与扩展性，可为高校或社区体育场馆数字化改造提供参考。

**关键词：** 智慧体育馆；Spring Boot；Vue 3；预约管理；协同过滤推荐

## Abstract

With the increasing demand for public fitness, traditional gymnasium management faces low efficiency and poor user experience in booking, operation, and resource allocation. This paper presents the design and implementation of a smart gym management system. The system adopts a front-end/back-end separated architecture: Spring Boot and Spring Data JPA on the back end, Vue 3 and Vite on the front end, and MySQL/H2 for data persistence. It supports two roles (users and administrators) and provides core functions such as venue browsing, booking, check-in, favorites, ratings, wallet recharge, and admin-side management. A collaborative-filtering-based recommendation strategy is introduced to improve personalized venue discovery. Practice shows that the system can stably support core workflows for small and medium-sized gym scenarios, with good maintainability and extensibility.

**Keywords:** Smart Gym, Spring Boot, Vue 3, Booking Management, Collaborative Filtering

## 第一章 绪论

### 1.1 研究背景

传统线下或分散式体育场馆管理模式通常依赖人工登记与电话确认，存在预约冲突、信息滞后、用户粘性低等问题。随着移动互联网和智能管理技术的发展，建设统一的数字化管理平台已成为场馆运营优化的重要方向。

### 1.2 研究意义

1. 对用户：提升场馆检索、预约、签到、支付与评价的整体体验。  
2. 对场馆：提升资源利用率，减少人工成本，增强运营透明度。  
3. 对管理者：支持后台管理与数据统计，为运营决策提供依据。  

### 1.3 研究内容

本文完成了一个智慧体育馆管理系统的需求分析、系统设计、核心模块实现与功能验证，重点实现了预约流程闭环与推荐能力融合。

## 第二章 需求分析

### 2.1 角色与业务需求

- 普通用户：注册登录、浏览场馆、预约场馆、签到入场、收藏场馆、评分评论、查看个人统计、余额充值。  
- 管理员：用户管理、场馆管理、预约审核与运营概览。  

### 2.2 功能需求

1. 用户认证与资料管理  
2. 场馆信息展示与详情查看  
3. 预约创建、状态管理与签到机制  
4. 收藏与评分评价  
5. 钱包余额、充值与预约扣费  
6. 个性化推荐（协同过滤）  
7. 后台管理与统计可视化  

### 2.3 非功能需求

- 易用性：界面清晰，操作路径短。  
- 可维护性：前后端分层，模块职责明确。  
- 可扩展性：预留推荐策略和业务规则扩展点。  
- 安全性：基础参数校验与接口异常处理。  

## 第三章 系统总体设计

### 3.1 架构设计

系统采用前后端分离架构：

- 前端：Vue 3 + Vite + Vue Router  
- 后端：Spring Boot + Spring Web + Spring Data JPA  
- 数据层：MySQL（生产可用）/ H2（开发调试）  

### 3.2 主要模块划分

- 用户模块（登录、注册、资料与余额）  
- 场馆模块（列表、详情、收藏）  
- 预约模块（创建、状态、签到）  
- 评价模块（评分与评论）  
- 推荐模块（协同过滤推荐）  
- 管理模块（用户/场馆/预约管理）  

### 3.3 数据实体设计（核心）

- User：用户基本信息、角色、余额等  
- Gym：场馆信息与价格等  
- Booking：预约记录、状态、签到标记与签到时间  
- Favorite：收藏关系与创建时间  
- Rating：评分、评论与创建时间  

## 第四章 系统实现

### 4.1 后端实现要点

1. **REST API 设计**：围绕用户、场馆、预约、收藏、评价提供标准接口。  
2. **预约业务规则**：支持预约创建、余额校验与扣费。  
3. **签到规则**：对已确认预约进行签到记录，保障预约流程闭环。  
4. **用户余额体系**：支持充值与统计查询中的余额展示。  
5. **推荐服务**：基于协同过滤思路生成个性化推荐结果。  

### 4.2 前端实现要点

1. **页面组织**：首页、登录注册、场馆详情、个人中心、预约页、收藏页、管理后台。  
2. **路由与权限展示**：按角色区分普通用户端与管理端入口。  
3. **交互体验**：预约反馈、签到按钮状态、余额充值弹窗、统计卡片展示。  
4. **接口联动**：根据后端返回结构展示成功/失败原因，提升可理解性。  

### 4.3 关键优化与修复（开发实践）

- 完善收藏入口与路由接入；  
- 增强首页与个人中心统计信息；  
- 增加充值、扣费、签到等业务闭环；  
- 补充邮箱格式前后端双重校验；  
- 修复字段命名导致的 JPA 方法解析冲突问题（统一签到相关命名）。  

## 第五章 系统测试与结果分析

### 5.1 测试思路

- 功能测试：覆盖用户主流程（注册→浏览→预约→签到→评价）。  
- 接口测试：验证参数校验、异常响应与边界场景。  
- 页面联调测试：验证前端与后端数据一致性。  

### 5.2 重点验证场景

1. 余额不足时预约失败并返回明确提示。  
2. 已确认未签到记录存在时，限制继续预约（按业务规则执行）。  
3. 充值后余额与统计页面同步更新。  
4. 收藏、评分、预约记录在个人侧正确展示。  

### 5.3 结果分析

系统能够完成预期核心功能，主要流程稳定可用。前后端职责分明，便于后续增加支付、消息通知、推荐算法升级等能力。

## 第六章 总结与展望

### 6.1 工作总结

本文完成了智慧体育馆管理系统从需求分析到系统实现的完整过程，重点打通了预约、签到、余额与推荐等关键业务链路，实现了面向用户与管理员双角色的统一平台。

### 6.2 后续展望

1. 引入更丰富的推荐策略（内容画像、混合推荐、深度学习推荐）。  
2. 增加消息通知（预约提醒、签到提醒、活动推送）。  
3. 接入真实支付网关与订单流水审计。  
4. 增强权限控制、日志追踪与安全防护能力。  
5. 增加自动化测试与持续集成流程，提升交付质量。
