## 2. 后端改动（Spring Boot）

### 2.1 用户余额与充值

- 在用户实体中新增余额字段：`balance`
  - 文件：`gym-backend/src/main/java/com/gym/management/entity/User.java`
- `UserDto` 增加 `balance` 字段，保证前端能拿到余额
  - 文件：`gym-backend/src/main/java/com/gym/management/dto/UserDto.java`
- 增加“充值”业务方法与接口：
  - Service：`UserService.recharge(userId, amount)`
    - 文件：`gym-backend/src/main/java/com/gym/management/service/UserService.java`
  - API：`POST /api/users/{userId}/recharge`
    - 文件：`gym-backend/src/main/java/com/gym/management/controller/ApiController.java`
- 用户统计接口返回余额字段：
  - API：`GET /api/users/{userId}/stats` 增加 `balance`
  - 文件：`gym-backend/src/main/java/com/gym/management/controller/ApiController.java`

### 2.2 预约扣费与预约接口调整

- 预约创建时进行余额校验并扣费：
  - 余额不足时报错：`余额不足`
  - 文件：`gym-backend/src/main/java/com/gym/management/service/BookingService.java`
- 预约接口返回结构从“直接返回 Booking”调整为“{ success, booking/message }”
  - API：`POST /api/book`
  - 文件：`gym-backend/src/main/java/com/gym/management/controller/ApiController.java`

### 2.3 签到系统（关键规则：未签到不可继续预约）

#### 新增字段

- 在预约实体中新增字段：
  - `attended`：是否签到（默认 false）
  - `signInTime`：签到时间
  - 文件：`gym-backend/src/main/java/com/gym/management/entity/Booking.java`

#### 新增接口

- 签到接口：
  - `POST /api/bookings/{bookingId}/sign-in?userId=...`
  - 文件：`gym-backend/src/main/java/com/gym/management/controller/ApiController.java`

#### 核心限制逻辑

- 当用户存在“已确认（CONFIRMED）但未签到（attended=false）”的预约时，禁止创建新预约：
  - 触发提示：`您还有已确认但未签到的预约，请先完成签到后再预约新场馆`
  - 文件：`gym-backend/src/main/java/com/gym/management/service/BookingService.java`
- Repository 增加查询方法用于限制判断：
  - `findByUserAndStatusAndAttended(User user, String status, Boolean attended)`
  - 文件：`gym-backend/src/main/java/com/gym/management/repository/BookingRepository.java`

#### 重要修复（服务启动失败原因与解决）

初版实现中使用了 `signedIn` / `isCheckIn` 等命名，Spring Data JPA 会把方法名拆分解析，导致 `PropertyReferenceException`（例如把 `signedIn` 拆成 `signed + In`）。最终统一改为 `attended` 字段，规避关键字/拆分冲突。
